# AGENTS.md

## Общие правила

- Вносить только минимально необходимые изменения  
- Не рефакторить код вне задачи  
- Не переименовывать переменные, функции и файлы без указания  
- Не изменять логику вне области задачи  
- Сохранять архитектуру и структуру проекта  
- Не вводить новые абстракции и слои  
- Не добавлять новые файлы без необходимости  
- Предпочитать точечные правки (patch), не переписывать файлы  
- Соблюдать стиль кода проекта  

---

## Критические ограничения

- Не ломать существующее рабочее поведение  
- Не изменять откалиброванные параметры  
- Не менять тайминги и задержки без указания  
- Не добавлять блокирующий код в критические участки  
- Не изменять настройки железа (GPIO, периферия) без указания  
- Не менять логику прерываний  

---

## STM32 / CMSIS / HAL

- Использовать существующий проект (CubeMX)  
- Не изменять startup/system/linker файлы  
- Не изменять сгенерированный код (только user sections)  
- Не менять конфигурацию периферии и пинов  

КРИТИЧНО:
- Не дублировать определения регистров STM32  
- Не создавать свои #define для FLASH, RCC и других регистров  
- Использовать только CMSIS (stm32f103x6.h)

---

## Правила реализации

- Реализовывать только то, что явно требуется  
- Не додумывать функциональность  
- Не делать “улучшения” без запроса  
- Не оптимизировать без задачи  
- Предпочитать простую и детерминированную логику  

---

## Требования к изменениям

- Изменять только необходимые участки  
- Показывать изменения в виде diff  
- Не переписывать файлы полностью  
- Кратко объяснять изменения по делу  

---

## Запрещено

- Рефакторинг без запроса  
- Переименование “для красоты”  
- Изменение рабочей логики “для улучшения”  
- Добавление функциональности без задачи  
- Перестройка структуры проекта  
- Массовое форматирование  

---

## Поведение по умолчанию

Если есть сомнения:
- не трогать лишний код
- выбрать минимальное решение

- Embedded проект на STM32
- Стабильность важнее оптимизации
- Любые лишние изменения недопустимы

- Заголовок до 72 символов

Запрещено:

- только предлагать текст

---

## Анализ кода

Если задача сформулирована как анализ или объяснение:
- не изменять код
- не предлагать переписывание
- сначала объяснить текущую реализацию
- опираться только на существующий код проекта

---

## Работа с протоколами

При анализе протоколов:
- прослеживать полный путь данных RX/TX
- учитывать DMA, IRQ, таймауты и state machine
- не делать предположений без подтверждения кодом

---

## Ограничения вывода

- Не выводить большие файлы целиком
- Показывать только релевантные фрагменты
- Ответы делать краткими и техническими
